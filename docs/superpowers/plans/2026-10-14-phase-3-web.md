# Zoo Vision Phase 3 (Web on the API), Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement the **backend developer** tasks (F1–F5) task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The **FE team** tasks (T1–T8) state a goal, the contract to use and acceptance criteria; the FE team plans and builds them its own way.

**Goal:** `zoo-vision-fe` runs entirely on the NestJS API: login with the API's sessions, every number from report
endpoints, live updates over the WebSocket, and a Config menu and System log for managers and superadmins. No
database, no engine proxy, no shared password.

**Architecture:** The browser calls the API through Caddy on one origin (`/api/v1`, `/ws`, `/media`). The Next.js
server never calls the API. Pages are client components using TanStack Query hooks that orval generates from the
backend's `openapi.json`, pulled at a contract tag. One socket.io connection (`useLive`) turns `data.changed` into
query refetches and feeds live camera status. Use-case report pages live in `src/usecases/<id>/`.

**Tech Stack:** Next.js 16, React 19, Tailwind 4, recharts, lucide-react (all already here); added axios,
`@tanstack/react-query`, `socket.io-client`, orval, Vitest + Testing Library + jsdom.

**Spec:** the Phase 3 design in the backend repo:
`https://github.com/Aryaputra34/zoo-vision/blob/<tag>/docs/superpowers/specs/2026-10-14-phase-3-web-on-api-design.md`
(sections 1 and 5 are the frontend's). The contract details are in `src/contract/fe-contract.md` after each pull.
The backend half is `zoo-vision/docs/superpowers/plans/2026-10-14-phase-3-web-on-api.md`.

## Decisions this plan makes beyond the design

1. **orval generates TanStack Query hooks** with axios through one mutator (`apiFetch`), in `tags-split` mode. Hook
   names are `use` + the operationId: `useCamerasList`, `useReportsEventStats`.
2. **Every page is a client component.** `page.tsx` files stay thin and render a component from
   `src/usecases/<id>/` or `src/features/<area>/`.
3. **Pages not yet ported show a `<Rebuilding />` placeholder** after F3, so `main` always builds while the FE team
   works through T1–T8.
4. **Query defaults:** `staleTime` 30 s, refetch on window focus, one retry except for 4xx. Freshness comes from
   `data.changed`, not polling.
5. **`session.ended` with `role_changed` is not a logout:** refetch `/auth/me`, then reconnect the socket. The
   other reasons, and a refused handshake, go to `/login?next=<current path>`.
6. **Report rows are sparse:** `fillBuckets` (F5) fills missing buckets with zeros before charting.
7. **Vitest** for unit and hook tests. Playwright is the FE team's call (parent spec section 8).

## Review Focus

1. **The session ends while a page is open** (expiry, disabled, logout in another tab). Expected: the next API
   call or `session.ended` sends the user to `/login?next=<page>`, and after logging in they are back on that
   page. Tests in F2 and F4.
2. **A contract pulled from a local backend checkout is committed by mistake.** Expected: CI fails. Test in F1.
3. **Redis is down, so status stops.** Expected: "Data live terhenti" after 10 s instead of old numbers shown as
   live. Test in F4.
4. **Two people save the same camera's zones.** Expected: the second gets `STALE_VERSION`, is offered a reload,
   and nothing is overwritten. Acceptance in T2.
5. **A role is lowered while the page is open.** Expected: the menu updates after the reconnect, and an action
   the API now refuses shows its `ROLE_REQUIRED`/`FORBIDDEN` message instead of failing silently. Tests in F2 and
   F4.

  - a tag: downloads `apps/api/openapi.json`, `packages/contracts/generated/web/index.d.ts` and
    `docs/fe-contract.md` from `https://raw.githubusercontent.com/Aryaputra34/zoo-vision/<tag>/…`;

- `orval.config.ts`: input `src/contract/openapi.json`; output `src/api/generated`, mode `tags-split`, client
  `react-query`, httpClient `axios`, mutator `apiFetch` from `src/api/http.ts`.
- `src/api/http.ts`:
  ```ts
  export class ApiError extends Error { statusCode: number; code: string; errors?: { path: string; message: string }[] }
  export const http: AxiosInstance;   // no baseURL: the paths in openapi.json already start with /api/v1 (or /media)
  export function apiFetch<T>(config: AxiosRequestConfig, options?: AxiosRequestConfig): Promise<T>;
  export function onUnauthenticated(handler: () => void): () => void; // F2 registers the redirect
  export const backendHealth: { subscribe(fn: (down: boolean) => void): () => void; down(): boolean };
  ```
  - A response body with `code` → `ApiError` with it; without one → `code 'UNKNOWN'` and the status.
  - No response at all → `ApiError {statusCode: 0, code: 'NETWORK'}`.
  - 503 or `NETWORK` marks the backend down; the next success marks it up.
  - 401 calls the `onUnauthenticated` handlers.
  - Media and CSV are plain URLs (`/media/...`, `/api/v1/exports/...`), not client calls.
- `src/app/providers.tsx` (`"use client"`): `QueryClientProvider` with decision 4's defaults; `layout.tsx` wraps
  the shell in it.

### Task T1: Cameras (FE team)

**Goal:** managers and superadmins see every camera with its live state and edit what their role allows;
superadmins add and remove cameras.

**Contract (v0.1):** the camera routes (`camerasList`, `camerasGet`, `camerasCreate`, `camerasUpdate`,
`camerasRemove`, or as named in `openapi.json`); `GET /camera-status`; `usecasesList` for the use case picker;
`fe-contract.md` §6 for the fields each role may change.

**Routes:** `/config/cameras`, `/config/cameras/new`, `/config/cameras/[id]`.

| Accepted when |
|---|
| The list shows id, name, area, use case label, enabled, online/offline, and applied vs active version; MANAGER and SUPERADMIN only (`RequireRole`) |
| Create and delete are visible to SUPERADMIN only; `CAMERA_HAS_DATA` on delete explains "nonaktifkan saja" |

| Validation errors (`VALIDATION_FAILED`, `errors[].path`) show next to their fields |

### Task T2: Zone editor, settings form, versions (FE team)

**Goal:** draw zones, tripwires and tables on the camera's latest frame, set thresholds, save, and see the engine
apply it, with history and rollback.

**Contract:** `usecasesList` (`settingsSchema` with `x-geometry`, `x-minRole`, `default`); the camera config
routes (`GET /cameras/:id/config`, `POST /cameras/:id/config` with `baseVersion`, `GET …/versions`,
`GET …/versions/:version`, `POST …/rollback`); `GET /cameras/:id/frame`; Saved → Applied by polling
`GET /cameras/:id/status` until v0.3, then `status.snapshot` via `useStatus`. `fe-contract.md` §5–6.

**Route:** `/config/cameras/[id]/zones` (MANAGER and up).

| Accepted when |
|---|
| Every schema node with `x-geometry: "polygon"` or `"line"` is drawn and editable, including inside arrays of objects (the restaurant table list: add, rename, delete tables; each with `id`, `name`, polygon) |
| Coordinates are stored 0–1 and clamped to the frame; a polygon needs at least 3 points before it can be saved |
| New zones and tables get ids matching `^[A-Za-z0-9_-]{1,32}$`, unique within the list, never reused after a delete |
| The threshold form is generated from the rest of the schema, with defaults shown; `x-minRole` fields above the user's role are disabled |
| Save sends `baseVersion`; `STALE_VERSION` offers to reload the latest version and never overwrites (Review Focus 4) |
| After save: "Tersimpan", then "Diterapkan ✓" when `appliedVersion` reaches the saved version, or "Ditolak: <reason>" from `configError` |
| History lists versions with author and time, shows a diff against the current one, and rolls back (rollback creates a new version) |
| No frame yet (404) → "Belum ada gambar dari kamera" on a blank 16:9 canvas, drawing still possible |
| Component tests cover: normalising and clamping points, the 3-point rule, id generation |

### Task T5: Overview, Vehicles, Cashier, Restaurant (FE team)

**Goal:** rebuild the four report pages on the report endpoints, keeping today's layout. Copy the pattern of
`src/usecases/horse_riding/RidesPage.tsx`.

**Contract (v0.2; v0.3 for live tiles):** `fe-contract.md` reports, lists, CSV and media sections.

| Page | Numbers and where they come from |
|---|---|
| Overview | crossings by direction: events stats `types=vehicle_crossing,horse_crossing`, `groupBy=type,data.direction`, `bucket=day`; alerts: `groupBy=severity`; capacity alerts: `types=capacity_alert`, `groupBy=data.level`; unattended minutes: interval stats `kind=desk_unattended`, `bucket=day`; peak occupancy and its time: metric series `name=occupancy`, `agg=max`, `bucket=5m`; tables seated and average stay: interval stats `kind=table_session`; cameras online: `useStatus` |
| Vehicles | per hour by direction: `groupBy=data.direction`, `bucket=hour`; type × direction table: `groupBy=data.vehicleType,data.direction`, `bucket=day`; the crossing list filtered by direction and type: events list `where=data.direction:ENTRY,data.vehicleType:car` |
| Cashier | per desk: unattended total (`kind=desk_unattended`, `groupBy=camera`, `bucket=day`) and per hour (`bucket=hour`); alert counts (`types=cashier_unattended,customer_waiting`, `groupBy=camera,type`); longest absence and wait (`max=absentSec`, `max=waitingSec`); current state from `useStatus` (`live.state`, `clerkCount`, `visitorCount`); the alert list |
| Restaurant | occupancy curve (`agg=max`, `bucket=5m`); busy minutes (`above=` the camera's `warningCapacity` from `live` or its settings); capacity alerts by level; tables: seated and average stay (`kind=table_session`), live table states from `useStatus` (`live.tables`) |

| Accepted when (every page) |
|---|
| No number is computed from raw event lists; every one comes from a stats or series endpoint |
| Gaps are filled with `fillBuckets`; charts keep operating hours (08–17 at least) |
| The page refreshes on `data.changed`; live tiles show "—" with "Kamera offline" when the status is null, and the paused badge when `paused` |
| Evidence through `EvidenceButton`; CSV links carry the page's filters |
| A day with no data shows the page's empty state, not an error |
